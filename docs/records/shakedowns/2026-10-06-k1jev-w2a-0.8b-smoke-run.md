# K1-Jev W2a 0.8B smoke run (2026-10-06)

Recorded on 2026-10-06 in a comment on [PR #415](https://github.com/kaineone/kaine/pull/415) (K1-Jev schema v2), and copied here verbatim so it survives the PR. It is the acceptance run for task 4.1 of the `k1-jev-decision-model` change.

**W2a 0.8B smoke run (task 4.1 acceptance), recorded at the freeze.** It ran on schema v1, so it tests the pipeline only. Real training waits for the v2 rebuild.

**Setup:**
- base: `Qwen/Qwen3.5-0.8B` at revision 2fc06364;
- trainer: the #382 head (8f9248ec, now on main);
- data: the v1 assembled set, gold excluded: 47,623 train and 4,538 dev;
- settings: LoRA rank 8, batch 8, 1 epoch, on one 12 GB GPU.

**Outcome: completed.**
- 5,953 of 5,953 steps in 38:58 (2,338 s); peak VRAM 4,388 MiB.
- final train loss 0.316; dev loss 0.173; dev accuracy 0.958.
- The dev accuracy is over the trainer's first 2,000 dev rows: all 1,038 synthetic items plus 962 Banking77, and no MultiNLI. It is an aggregate only.
- The adapter, the merged bf16 checkpoint and a resumable checkpoint at step 4,816 (with `trainer_state.pt`) are on the bulk drive under `k1jev/runs/w2a-0.8b-smoke`.

**What the run record pins:** the trainer commit (8f9248ec), the seed and data-order seed (20261005), train and dev SHA-256, the schema version (1) and digest, and the hyperparameters.

**Gaps:**
- `base_revision` is **null**. With a base loaded from a local directory, `config._commit_hash` is None. The fix: read the revision from the directory's `.cache/huggingface/download/*.metadata` files (their first line is the commit), require them all to agree, and fail closed if they don't.
- The data manifest's own SHA-256 isn't recorded, only the train and dev hashes.
- **Not done because of the freeze (no new GPU jobs):** per-question and per-disputed-cell dev accuracy, and the kill-and-resume test. Both should run on the v2-rebuilt data.
