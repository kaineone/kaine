## Why

On 2026-10-31 the operator decided that KAINE's workspace will carry content, built as option F of the global-latent-workspace comparison: a code `z_k` learned from the processors' perceptual latents and sent back down as predictions (change `workspace-content-code`). Content-bearing memory, grounding and working memory follow it. Every one of these components holds values computed from perceptual latents. The comparison report's finding F10 names the problem: the current privacy rules were written for a system with no such values, so a content code's logging and persistence policy would be inherited by accident unless it is designed first. The operator's decision fixes the principle: latent-derived content may live in working state and in learned weights; it is never logged, never stored as an episode, and it is stripped by the privacy filter. This change turns that principle into a rule the code can enforce, and it is the prerequisite for every content-bearing component (build order item 2).

The existing rules do not cover latent-derived values, and the persisting surfaces are more numerous than one choke point:

- **The vector rule is by name and length.** The privacy filter removes the named vector fields (`latent`, `peripheral`, `foveal`, `temporal_context`, `feature_vector`) and any unnamed numeric list of 16 or more numbers (`kaine/privacy_filter.py`, `VECTOR_BACKSTOP_MIN_LEN`). A content code of 8 numbers, an interoceptive prediction decoded from a code (8 numbers), or any projection published under a new key passes it.
- **Not every persisting surface uses the filter, and not every record uses the sink.** The curated research log, the dashboard stream and its record use the filter. The raw bus archive writes verbatim events once both attestations are set (spec `research-event-log`). The workspace trajectory copies broadcast metadata wholesale (`kaine/evaluation/trajectory.py:55`). The intent log, the sleep corpus, the voice-alignment records and the divergence log write through `kaine/persistence/encrypted_jsonl.py`, not the JSONL sink. Fork snapshots, preservation bundles and the rolling resume checkpoint (written each entity minute by its own path, `kaine/lifecycle/resume_checkpoint.py:178`) hold whatever each module's `serialize()` returns, and nothing checks it. Python log messages are not checked at all.
- **The organ's renderings format every key of a template-less event.** `audition.perception` has no numeric template. In the shipped felt mode the language module still builds a numeric rendering of the coalition, and for that event it falls back to `fallback_template`, which formats every payload key (`kaine/faithful/templates.py:536-541`). The result is written into the intent log, the organ's training corpus (`kaine/modules/language/module.py:1058-1075`). With the content code on, an acoustic latent and an ascending error would land there.
- **Snapshots already persist latent statistics.** `LatentForwardModel.buffer_summary()` writes the per-feature mean and variance of the last 16 clip latents into every snapshot and preservation bundle (`kaine/modules/vision/forward.py:503`, `kaine/modules/vision/module.py:996`). The auditory and acoustic forward models do the same (`kaine/modules/audition/module.py:1123,1135`), and the acoustic summaries of a non-running encoder are carried into every future snapshot (`:1126`). Sixteen clips are about six seconds of one shot, so the mean is close to a single clip embedding of the last thing the entity saw, and clip embeddings can be partly inverted to images (archived change `2026-10-03-workspace-graph-only-recording`). Nothing reads these summaries back on restore.
- **The bus's disk copy is unbounded by its caps.** Redis runs with its append-only file on (`compose/kaine.yml:102-115`), so every published entry, latents included, reaches disk and stays there after trimming until the next rewrite.
- **Episodic memory's omit list is narrower than the language module's heard rule.** The store drops the payloads of `audition.transcription` and `embodiment.visual.raw` only (`kaine/modules/episodic_memory/module.py:573-578`). The language module's heard rule also covers `embodiment.chat` and heard-text fields at any depth (`kaine/modules/language/context.py:271-302`). The design-only change `episodic-recall-content` fixes this in its first PR, which is now pulled forward.

## What Changes

- **One latent rule, by provenance.** A value is latent-derived when it is computed from a perceptual latent, or from another latent-derived value, and keeps per-dimension information: codes, projections, decoder outputs and predictions in a latent space, residual and gradient vectors, and per-dimension statistics over any window. Scalar reductions (norms, distances, mean squared errors, ratios, information gains, counts) are not latent-derived. Learned parameters are not values under this rule; they are identity and follow the identity rules.
- **One tag.** Latent-derived values travel only inside a mapping under the reserved key `latent_derived`, at any depth. Perceptual latents keep their existing names. `kaine/privacy_filter.py` gains `LATENT_FIELDS` (the vector fields plus `latent_derived`) and `strip_latent()`, which removes those keys at any depth regardless of length and walks lists, tuples and numpy arrays. `latent_derived` joins the vector fields, so the diagnostics filter and the episodic store's `strip_vectors` remove it too.
- **The strip points.**
  - `AsyncJsonlSink._encode_line` applies `strip_latent()`, so every sink record is covered whether it arrives through `write`, `write_sync` or `enqueue` (research log, ignition, incident and dashboard records, the raw archive, the workspace trajectory, every observer).
  - `encrypted_jsonl.encode_record` and `rewrite_encrypted` apply it (intent log, sleep corpus, voice-alignment records, divergence log).
  - The faithful and felt renderers strip each payload before any template or fallback, and `audition.perception` gains a numeric template.
  - The workspace broadcast record removes each selected member's `latent_derived` mapping.
  - One helper strips module states in every module-state capture: fork snapshots, preservation captures and the resume checkpoint. A module state holds no latent-set value except learned parameters that the module reads back on restore. A state that holds one has it stripped, the module named in the snapshot metadata and an error logged. A preservation is never refused for it.
  - The vision and auditory buffer summaries become content-free scalars, carried acoustic summaries included.
  - Episodic memory stores no latent-set value, with the heard rule applied first, then the raw-perceptual omit, then `strip_latent()`. Under the ruling on design open question 2 (option b, 2026-11-01), a content code may be stored only in the entity's own encrypted episodic store, in a dedicated identity-bound field, never in trace text, logs, research records, the intent log or the organ's corpus.
  - Python log calls never format a latent-set value.
- **The bus (design open question 1, ruled option B on 2026-11-01).** Latent values never enter a bus stream that Redis persists. Producers strip every latent field before publishing on the main bus, perceptual latents included, and the values a consumer needs travel on companion streams of a second Redis instance that is never persisted, with caps of at most `[privacy].companion_stream_maxlen` (default 12000). The producer writes the companion entry first and the main entry records its id, so a consumer never sees a main entry before its companion. The companion helpers take a declared field set, so `heard-text-volatile-bus` reuses the same instance and check for heard and spoken text. The boot refuses a declared companion producer when the volatile instance is missing, persisted or over-capped.
- **Encryption fails closed.** A latent producer refuses to start unless state encryption is in effect and `[preservation].require_encryption` is true.
- **Offline stimulus features are outside the rule.** Latents computed entity-free from stimulus files by tools scripts (the cross-modal decodability check is one) describe the stimulus, not an entity's experience. They never enter an entity's state tree or the shipped image.
- **Tests.**
  - A persistence canary: an entity-free run with every persisting surface on, the language module on a fake organ, a file-backed episodic store and the resume checkpoint, in which no latent-set value produced in working state appears in any persisted file, decrypted, at any precision a writer uses, as text or as packed binary floats; no main-bus publish carries a latent field.
  - A publisher review test: every numeric list, tuple or array a module publishes sits under a latent field or a reviewed non-latent key.
  - Filter, sink, encrypted-writer, renderer, trajectory, broadcast-record, module-state, buffer-summary, bus, encryption and log-capture tests.

## Capabilities

### New Capabilities

- `latent-content-privacy`: the latent rule, its tag, the strip points, the bus rule, the encryption check and the canary test.

### Modified Capabilities

- `research-event-log`: the diagnostics filter removes `latent_derived`; the raw archive is verbatim except for the latent fields.
- `vision-predictive`: the serialized buffer summary holds content-free scalars only.
- `audition-predictive`: the same for the auditory and acoustic buffer summaries, including carried entries of non-running encoders.
- `episodic-memory`: stored traces hold no latent-set value outside the identity-bound field, and the order of the store-time rules is fixed.
- `language`: renderings of an event never format a latent field, and `audition.perception` has a numeric template.
