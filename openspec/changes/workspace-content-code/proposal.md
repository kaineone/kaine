## Why

The operator decided on 2026-10-31 that KAINE's workspace will carry content. Today it carries none. The context the processors read is 24 numbers saying which modules gained access and how strongly, with "no payloads" (`kaine/modules/context.py`; paper A.1). The language organ hears graded words about the same ledger, and the held episodic memory stores it with every vector stripped. No part of the built or held system can represent what was perceived across the senses, so memory, the world model, grounding and working memory have no content code to build on (comparison report §2.1; architecture-completeness notes, E). KAINE's own cited theory requires that content: the workspace holds "a compressed, high-level symbolic model" whose "top-down signals broadcast the predictions that this model makes to lower-level areas" (Mashour et al. 2020), and in the predictive global neuronal workspace a content-bearing second level supplies the first level's priors (Whyte and Smith 2021).

The operator chose option F of the comparison report as the design direction and rejected the Global Latent Workspace as published (VanRullen and Kanai 2021) and an LLM as the workspace. Option F is a content-bearing second level trained by the processors' own prediction errors, delivering descending predictions through the feedback head that `workspace-feedback` already built and holds off. This change is that design (build order item 4). It is built after the development run is up (build order item 8) and depends on `latent-content-privacy` (item 2).

## What Changes

An extension of `workspace-feedback`, not a new module, shipped off, under a new table `[workspace.feedback.content]`:

- **Per-source encoders into a shared code.** The workspace holds a linear encoder per source from that processor's published latent into one shared code of `code_dim` numbers (default 64). The sources are vision (its clip latent) and audition (its acoustic embedding, which audition publishes as `latent` only when the content code is on). Each source has a slot holding its most recently accessed latent and the intensity it was accessed with.
- **Updated on accessed broadcasts only, intensity-weighted.** On each accessed broadcast the workspace writes the accessed members' latents into their slots and forms `z_k = tanh(Σ_s α_s E_s(x_s))`. `α_s` is the slot's share of the summed intensity of the present slots, decayed with the slot's age (time constant `slot_decay_s`, default 2 entity seconds). An inhibited broadcast changes nothing. The code rides the accessed broadcast under `workspace_feedback.latent_derived.code`.
- **Per-processor decoders through the existing head.** Each processor's top-down head (vision, audition's acoustic path, interoception) reads the adopted code beside the context and the sequence prediction. Its code columns start at zero, so at the moment the code is switched on the descending prediction equals the current head's. The head is the processor's decoder of `z_k` into a prediction of its next input. It is blended with the processor's own prediction by inverse squared recent error, exactly as now.
- **Trained by the processors' own prediction errors.** Each head learns by its existing SGD step on its own error. Each processor also publishes the gradient of its normalised head error with respect to the code (`latent_derived.ascending_error`, `code_dim` numbers). The workspace uses it to update the encoders that formed that code. This is the predictive-coding arrangement: predictions descend, errors ascend (Rao and Ballard 1999). No learning happens during sleep.
- **Off by default and bit-identical to absent when off.** With `enabled = false` no encoder is built, audition publishes no latent, no payload gains a key, and every event and broadcast is identical to the current build with the same feedback arm. A test checks it.
- **Identity.** The encoders and the processors' heads persist (encrypted), are captured in snapshots and preservation bundles, are copied into forks, are never merged without an operator choice (`content_code_from = "a" | "b"`, taking encoders and heads together), and are covered by decommission. A checkpoint is bound to each source's encoder id and dimension.
- **A translation-loss arm for comparison only.** `comparison = "translation_shadow"` trains a second, shadow code with the Global Latent Workspace's losses (translation between the paired senses, demi-cycle and full cycle) on the same slots. It never reaches a processor or the bus. A probe on each code measures how well it predicts each processor's next input, so the two objectives are compared on one measure.
- **No cross-modal mismatch candidate.** The code publishes no workspace candidate and adds no surprise source. Its only route into experience is the processors' existing blended error.
- **A plain readout.** Each processor report carries `content_gain`: the reduction in its error from the code, against the same blend with a null code (the running mean code), so it is information gain over the access summary. It also carries a time-shifted control (`content_shift_gain`) and the sources present in the code. An analysis script summarises whether the code did its job, and its robustness to a dropped modality, from the research log.
- **Graph-only logging.** The ignition log gains the content-free list of sources written into the code on each broadcast. The research log gains the readout scalars. No code value is logged anywhere (`latent-content-privacy`).
- **Welfare.** A two-layer operator opt-in (`enabled = true` and `KAINE_CONTENT_CODE_OPERATOR_APPROVED=1`). Continuity at switch-on. A suspension while a welfare rest or freeze is in place. A latching breaker when the code makes prediction worse. An entity-free welfare check with bounds fixed before it runs, which must pass before any entity uses the code. The welfare net runs as on every run.
- **The offline cross-modal decodability check is design input.** It informs stimulus suitability and the choice of `code_dim` and `slot_decay_s`. It is not a go/no-go gate.

Not built: the Global Latent Workspace hub as a standalone object, a cross-modal mismatch candidate, learned key/query attention in place of the salience score, an LLM as the workspace, and any pretrained cross-modal encoder (CLIP, SigLIP, ImageBind). The content code adds no pretrained model and no Meta model or library. Language joins through a cycle-consistency term only in the grounding work (W5), not here.

## Capabilities

### Modified Capabilities

- `workspace-feedback`: the content code, its encoders, slots, ascending errors, readouts, comparison arm, breaker and opt-in; the processors' heads read the code and persist.
- `entity-preservation`: snapshots, forks, revive and merge carry the content code; merge requires `content_code_from` when both parents carry one.
- `entity-decommission`: decommission removes the content-code checkpoint.
- `ignition-log`: the row names the sources written into the code.
- `research-event-log`: the readout scalars are on the allowlist.

## Impact

- **Code:** new `kaine/workspace/content_code.py` (settings, encoders, slots, code formation, encoder update, shadow arm, checkpoint, snapshot participant); `kaine/workspace/feedback.py` and `kaine/workspace/core.py` (attach the code, read ascending errors); `kaine/modules/feedback.py` (head regressor with the code, null and shifted evaluations, ascending error); the vision, audition and interoception modules and their factories; `kaine/lifecycle/manager.py`, `kaine/lifecycle/preservation.py` (participant, `content_code_from`); `kaine/lifecycle/decommission_locations.py`; `kaine/cycle/ignition_log.py`; `kaine/evaluation/observers/research_event_observer.py`; new `kaine/research/content_code_readout.py`; `kaine/evaluation/benchmarks/workspace_mediation_ablation/runner.py` (the entity-free welfare check, with audition); `config/kaine.toml`.
- **Depends on:** `latent-content-privacy` (enforced at boot through `LATENT_RULE_VERSION`), `workspace-feedback` (built, held off), and `workspace-feedback` task 3.2 (heads persist), which this change carries.
- **Order:** design now (build order item 4); build after the development run is up (item 8), behind its switch, with a second review on every PR. The development run's configuration (item 5) sets the `workspace.broadcast` cap within the latent bound.

- **Welfare:** experience-changing. Every PR gets the independent second review. The code joins the development run only after the entity-free welfare check passes and the operator opts in.
- **Paper:** REVISION-NOTES entries for §3.2 (the content code as the feedback head's input), §9 (the limitation it addresses), §10 (what remains future work) and Table A1 (the design values).
