## Why

The operator decided on 2026-10-31 that KAINE's workspace will carry content. Today it carries none. The context the processors read is 24 numbers saying which modules gained access and how strongly, with "no payloads" (`kaine/modules/context.py`; paper A.1). The language organ hears graded words about the same ledger, and the held episodic memory stores it with every vector stripped. No part of the built or held system can represent what was perceived across the senses, so memory, the world model, grounding and working memory have no content code to build on (comparison report §2.1; architecture-completeness notes, E). KAINE's own cited theory requires that content: the workspace holds "a compressed, high-level symbolic model" whose "top-down signals broadcast the predictions that this model makes to lower-level areas" (Mashour et al. 2020), and in the predictive global neuronal workspace a content-bearing second level supplies the first level's priors (Whyte and Smith 2021).

The operator chose option F of the comparison report as the design direction and rejected the Global Latent Workspace as published (VanRullen and Kanai 2021) and an LLM as the workspace. Option F is a content-bearing second level trained by the processors' own prediction errors, delivering descending predictions through the feedback head that `workspace-feedback` already built and holds off. This change is that design (build order item 4), revised after an adversarial review (C1 to C17). It is built after the development run is up (build order item 8) and depends on `latent-content-privacy` (item 2), `welfare-signal-unblended` and `fork-merge-module-weights`.

## What Changes

An extension of `workspace-feedback`, not a new module, shipped off, under a new table `[workspace.feedback.content]`:

- **Per-source encoders into a shared code.** The workspace holds a linear encoder per source from that processor's latent, standardised per dimension, into one shared code of `code_dim` numbers (default 64). The sources are vision (its clip latent) and audition (its acoustic embedding, which audition publishes inside its `latent_derived` mapping only when the content code is on). Each source has a slot holding its most recently accessed latent and the intensity it was accessed with.
- **Updated on accessed broadcasts only, intensity-weighted, continuous.** On each accessed broadcast the workspace writes the accessed members' latents into their slots and forms `z_k = tanh(Σ_s α_s E_s(x̃_s))`, with `α_s` the slot's intensity decayed with its age (time constant `slot_decay_s`, default 2 entity seconds). There is no normalisation across slots, so one slot's arrival or expiry never rescales another's term. An inhibited broadcast changes nothing.
- **Per-processor decoders through the existing head.** Each processor's top-down head (vision, audition's acoustic path, interoception) reads the adopted code beside the context and the sequence prediction. A head is widened with zero code columns at switch-on, so the first descending prediction equals the current head's. The head is the processor's decoder of `z_k` into a prediction of its next input, blended with the processor's own prediction by inverse squared recent error, exactly as now.
- **Trained by the processors' own prediction errors.** Each head learns by its existing SGD step on its own error. Each processor also publishes the gradient of its normalised head error with respect to the code (`latent_derived.ascending_error`), with the normaliser and the timing pinned. The workspace averages it per code and processor and takes one guarded, max-norm-bounded encoder step. This is the predictive-coding arrangement: predictions descend, errors ascend (Rao and Ballard 1999). No learning happens during sleep.
- **The bus.** Pending `latent-content-privacy`'s open question 1 (recommended option B), the code, the ascending errors and the latents travel on volatile companion streams that Redis never persists. The novelty fingerprint excludes `latent_derived`, so the code adds no route into salience.
- **Off by default and bit-identical to absent when off,** checked by a golden trace recorded on the commit before the change.
- **Identity.** The encoders, standardisers and every head's code block are one unit in one encrypted checkpoint, written with every module-state capture. A new snapshot-participant seam carries it through snapshots, forks, restore (before module state), revive, merge from disk and decommission. Merge requires `content_code_from = "a" | "b"`, which takes the whole unit and every head's base block from that parent, exactly. The checkpoint is bound to each source's encoder id, pooling and dimension, and the code refuses to build without encryption in effect.
- **A translation-loss arm for comparison only.** `comparison = "translation_shadow"` trains a second, shadow code with the Global Latent Workspace's losses off the tick thread. It never reaches a processor or the bus. Probes on each code, including cross-modal probes, measure how well it predicts each processor's next input.
- **No cross-modal mismatch candidate.** The code publishes no workspace candidate and adds no surprise source. Its only route into experience is the processors' existing blended error.
- **A plain readout that can tell content from an echo.** Each report carries `content_gain` (against the running-mean null code), `content_cross_gain` (the code formed from the other senses only, the cross-modal readout), `content_shift_gain` (a code at least 60 entity seconds old) and the sources present. An analysis script reports them per processor and per film, with slot occupancy and dropped-modality robustness.
- **Graph-only logging.** The ignition log gains the content-free list of sources written into the code on each broadcast. The research log gains the readout scalars. No code value is logged anywhere.
- **Welfare.** A two-layer operator opt-in. Continuity at switch-on. The welfare signal is the own-model error, which the code cannot move (`welfare-signal-unblended`). The two feed defects are fixed first. A new entity-free welfare harness with real audition, sequence and affect on the films, two passes (one from a code trained entity-free on cached latents, discarded afterwards), bounds fixed in advance, and an engagement condition so the bounds cannot pass vacuously. A suspension while a welfare rest or freeze is in place. A latching breaker when the code makes prediction worse.
- **The offline cross-modal decodability check is design input.** `code_dim` stays at 64 and `slot_decay_s` at 2 s until the check is rerun at short lags; content-code runs use a learned audition encoder.

Not built: the Global Latent Workspace hub as a standalone object, a cross-modal mismatch candidate, learned key/query attention in place of the salience score, an LLM as the workspace, and any pretrained cross-modal encoder (CLIP, SigLIP, ImageBind). The shipped vision latent is CLIP-aligned; pending an operator ruling (design, open question 1) the content code requires mean pooling of the vision encoder's patch tokens. No Meta model or library is added. Language joins through a cycle-consistency term only in the grounding work (W5), not here.

## Capabilities

### Modified Capabilities

- `workspace-feedback`: the content code, its encoders, standardisers, slots, ascending errors, readouts, comparison arm, breaker and opt-in; the processors' heads read the code and persist. (`workspace-feedback` is still a change; it is archived before this delta.)
- `entity-preservation`: the snapshot-participant seam; snapshots, forks, restore, revive and merge carry the content code; merge requires `content_code_from` when both parents carry one.
- `entity-decommission`: decommission removes the content-code checkpoint and artifacts.
- `ignition-log`: the row names the sources written into the code.
- `research-event-log`: the readout scalars are on the allowlist.
